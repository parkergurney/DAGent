Replace the SDK client, keep the control plane.

Use Claude Code's installed CLI in print-mode stream JSON behind a small compatibility adapter. Preserve the scheduler's process contract and event semantics; preserve the host Claude authentication context; let the outer Seatbelt remain the filesystem and network boundary.

Recommended

Seatbelt → cli_worker adapter → claude -p

Launch one direct CLI subprocess per attempt with --input-format stream-json and --output-format stream-json. The adapter translates scheduler nudges into JSONL user messages and translates CLI records into the existing worker JSONL protocol.

Hard blocker

Do not isolate HOME in v1

A fresh private HOME or private CLAUDE_CONFIG_DIR fails login even outside Seatbelt. The normal host context succeeds with API variables removed.

Compatibility mapping

Startup

Require the first system.init record, then a successful first result. Classify authentication_failed, missing session id, non-success result, Seatbelt exec failure, and CLI exit before init.

Prompt / nudge

Initial execution contract is the first JSONL user message. A nudge becomes another JSONL user message; raw scheduler stdin stays unchanged because the adapter encodes it.

Completion

Accumulate assistant text until each turn's result. Parse DONE_CLAIM: or ASK: from the final turn text. Never use process exit alone.

Lifecycle

Outer process gets start_new_session=True; adapter and CLI share its process group. Existing SIGKILL + wait + idempotent teardown remains authoritative.

Accounting

Use only terminal CLI result aggregates for tokens and reported total_cost_usd/modelUsage. Do not sum assistant message usage.

Transcript

Persist raw stream JSONL per attempt outside the worker checkout, with an explicit Seatbelt write allowlist. Keep only bounded summaries in SQLite events.

Exact smoke shape

env -u ANTHROPIC_API_KEY -u ANTHROPIC_AUTH_TOKEN \
  -u CLAUDE_CODE_OAUTH_TOKEN -u CLAUDE_CODE_OAUTH_REFRESH_TOKEN \
  claude -p --input-format stream-json \
  --output-format stream-json --verbose \
  --include-partial-messages --replay-user-messages \
  --no-session-persistence --permission-mode bypassPermissions \
  --model <pinned-model>

Feed one JSON object per line: {"type":"user","message":{"role":"user","content":[{"type":"text","text":"..."}]}}. Keep --safe-mode or an equivalent constrained setting source in the implementation after validating that it does not change the host-login lookup; never use --bare, which the installed help says skips keychain reads.

Migration gates

Deterministic

Fake CLI stream parser tests; sentinel and auth/error classification; per-turn result accounting; malformed JSON; EOF after ASK; nudge encoding; process-group kill; transcript redaction/path checks; scheduler unchanged against existing FakeWorker scenarios.

Live, opt-in

Host subscription smoke with forbidden credentials unset; same smoke under Seatbelt with host auth context; one tool-writing task in a disposable worktree; ASK→nudge; stall→wait/restart; forced kill; hidden verifier read denial; two retries with durable candidate lineage.

Recommendation

Implement a new cli_worker transport adapter, leave scheduler/state/storage/verify/delivery logic intact, and make one-shot attempts the initial supported lifecycle. Live nudge can be enabled immediately because stream-json input keeps one process/session alive; retry always creates a fresh CLI process and uses the existing attempt candidate SHA rather than CLI session resume.

Open risk: the Seatbelt profile must allow the normal host Claude authentication context without allowing hidden benchmark material. Validate that boundary before changing the production worker selector.
